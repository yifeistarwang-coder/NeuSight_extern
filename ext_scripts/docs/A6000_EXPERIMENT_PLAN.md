# RTX A6000 实验计划

> 状态：待执行。已有代码、数据和硬件核查记录；环境、脚本适配和性能实验尚未完成。

**目标：冻结现有 NeuSight 预测器，检查它在未见过的 GPU 型号 RTX A6000 上，能否准确预测模型的推理和训练延迟，并定位误差来自哪些算子。**

已有训练数据包含同属 Ampere 的 A100，因此本实验检验的是“跨 GPU 型号泛化”。结果对应论文的 [Figure 7：端到端误差](https://arxiv.org/html/2407.13853v3#S6.F7)和 [Figure 8：算子误差](https://arxiv.org/html/2407.13853v3#S6.F8)。

## 1. Review 重点

| 需要判断的设计选择 | 当前方案与理由 |
|---|---|
| 第一阶段的范围是否合适 | 只评估 NeuSight，先回答 A6000 上的预测精度；其他预测器基线、算子融合、分布式训练留待后续。 |
| 能否检验未见 GPU 的泛化 | 固定五组预训练权重和原有 tile 表；A6000 实测只用于评测，不参与训练、调参或 tile 更新。 |
| 工作量是否可接受 | 沿用仓库的 24 个配置，各独立测量 3 轮；两张卡并行跑独立单卡任务，暂估 5–15 小时，预留一天。 |
| 如何判断实验完成 | 交付预测误差、测量波动和失败清单；不预设准确率通过阈值，误差大小就是实验结果。 |

## 2. 跑哪些配置

统一使用 **单卡、FP32、eager，关闭 TF32**。两张 A6000 各自运行完整模型。

| 模型（配置名） | 序列长度 | 推理 batch size | 训练 batch size |
|---|---:|---|---|
| BERT-Large（`bert_large`） | 512 | 8、16 | 2、8 |
| GPT-2 Large（`gpt2_large`） | 1024 | 4、8 | 1、4 |
| GPT-3 XL（`gpt3_xl`） | 2048 | 2、8 | 1、2 |
| OPT-1.3B（`opt_13`） | 2048 | 2、8 | 1、2 |
| GPT-3 2.7B（`gpt3_27`） | 2048 | 2、8 | 1、2 |
| Switch Transformer（`switchxl4`） | 512 | 1、2 | 1、2 |

共 **6 个模型 × 2 种模式 × 2 个 batch = 24 个配置；重复 3 轮，共 72 次正式采集**。矩阵沿用仓库的[预测脚本](scripts/asplos/run_pred_nvidia_neusight.py)和[采集脚本](scripts/asplos/run_label_nvidia.py)，便于对照已有实验。

被测模型使用随机初始化权重和合成输入，无需准备训练数据或下载模型权重。

## 3. 怎么测、怎么比较

- **预测输入**：现有 `MLP_WAVE` 的 LINEAR、BMM、VEC、SOFTMAX、LN 五组权重，原有 tile 表，以及新增的 A6000 硬件配置。
- **推理延迟**：给定序列的一次完整 forward；不包含逐 token decode。
- **训练延迟**：完整模型的 forward + backward；不包含 loss 计算和 optimizer step。
- **测量统计**：每轮执行 25 次，前向、反向分别取最快 5 次均值后相加，沿用现有代码。独立采集 3 轮，主结果取三轮中位数，同时报告最小／最大值和每轮 APE。
- **误差计算**：`APE = |预测 − 实测| / 实测 × 100%`。推理与训练分别汇总平均 APE（MAPE）、中位 APE、P90 APE 和有效配置数。

算子类别耗时先在每个 workload 内汇总，再计算误差；算子耗时之和与完整模型端到端延迟分别报告。

**与已有数据的关系：基础测量口径一致，三轮中位数、波动和 P90 为本次新增。** 跨 GPU 比较平均误差时使用共同有效配置；原矩阵的两个大 batch 训练配置没有现存 NVIDIA 主结果。旧数据缺少完整环境记录；旧算子反向分解字段需修正，类别均值需对齐样本集合和零值处理。核查证据见[附录第 8 节](A6000_EXPERIMENT_NOTES.md#8-与现有实验数据的一致性核查)。

## 4. 执行安排与预算

| 阶段 | 要做的事 | 进入下一阶段的条件 |
|---|---|---|
| 准备 | 对齐依赖，新增 A6000 JSON，适配 runner 和汇总脚本，固定输入版本 | 五组权重成功加载，输出能按卡和轮次隔离 |
| 试跑 | 两卡各跑 BERT、GPT-2 的小 batch 推理和训练，共 8 次；再补跑较大 GPT 和 Switch 配置 | 预测、实测、算子图和汇总能对应；已检查卡间差异并取得耗时估计 |
| 正式运行 | 先生成预测，再将 24 个配置按耗时分到两张卡，各采集 3 轮 | 每个配置都有完整结果或明确失败状态 |
| 汇总 | 生成误差表，检查异常和缺失项，必要时补充诊断 | 达到第 5 节交付要求 |

每卡同时只运行一个采集任务，同一配置的三轮尽量使用同一卡。试跑结果单独保存。

**预算暂估 5–15 小时，尚未通过试跑验证。** 其中正式采集按每项 5–15 分钟估算：`72 次 ÷ 2 张卡 × 5–15 分钟 = 3–9 小时`。试跑后更新预算；依赖问题、Switch trace 和重跑可能增加耗时。

开跑前主要需要解决三件事：

1. **软件环境**：优先对齐 PyTorch 2.1.0、Transformers 4.38.1；记录实际 CUDA/cuDNN 与 TF32 设置，旧数据未保存完整环境信息。
2. **脚本适配**：处理写死路径、默认四种预测器的汇总逻辑，以及两张同型号 GPU 的输出覆盖问题。
3. **可运行性**：大 batch 可能 OOM，Switch trace 需单独验证。失败如实记录，不静默缩 batch 或改精度；补充配置单列。

## 5. 最终交付与完成标准

| 交付物 | 必须包含 |
|---|---|
| 端到端结果表 | 各配置的预测 ms、三轮实测与每轮 APE、中位数、波动和预测／实测比值；三轮中位数对应的 APE 单列，推理／训练分别汇总 |
| 误差分解表 | 训练的 forward／backward 误差，以及 Linear、BMM、VEC/EW、Softmax、LayerNorm 的耗时与误差 |
| 实验记录 | 24 个配置的成功／OOM／失败状态、原因、有效重复数、卡间差异、耗时，以及环境和输入文件版本 |

完成时，预测与标签必须一一对应；失败或缺失项不能按零误差计入平均。原始数据、试跑和正式轮次可追溯，冻结的权重与 tile 表不受 A6000 标签影响。

硬件核查、设备 JSON 草案、试跑参数、命令、目录和代码待办见[执行附录](A6000_EXPERIMENT_NOTES.md)。
